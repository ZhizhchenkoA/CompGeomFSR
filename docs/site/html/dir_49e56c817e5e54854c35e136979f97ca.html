Geometry Workbench — документация

Назначение

Проект — Qt-приложение для интерактивной демонстрации алгоритмов компьютерной геометрии. Пользователь выбирает задачу, задаёт точки кликами или полями ввода, а страница передаёт данные в чистые C++-библиотеки и визуализирует результат.

Архитектура

  • src/apps/GeometryWorkbench — приложение Qt: главное окно, выбор задания, холст и формы.
  • src/lib/geometry — алгоритмы над точками и многоугольниками без зависимости от Qt: предикаты, пересечения, оболочка, Делоне и булевы операции.
  • src/lib/geometry_qt — единственный адаптер координат: экранная ось Y направлена вниз, математическая — вверх.
  • src/lib/bigint — знаковое целое произвольной длины и точный разбор десятичных чисел для задания 3.
  • src/lib/bezier — вычисление кривых Безье и уровней де Кастельжо для задания 13.

Алгоритмы не рисуют интерфейс. Они получают значения из модели, возвращают структуры результата, а GeometryCanvas переводит их в экранные координаты и рисует слои: сетку, исходные объекты, результат и легенду.

Основные алгоритмы

  • geometry::turn и geometry::cross — знак ориентированной площади треугольника.
  • geometry::intersectSegments — пересечение отрезков, включая точку, общий участок и вырожденные отрезки.
  • geometry::convexHull — монотонная цепь Эндрю с удалением дублей и коллинеарных внутренних точек.
  • geometry::delaunayTriangulation — инкрементальный Bowyer–Watson со структурой описанных окружностей.
  • geometry::convexPolygonBoolean — операции пересечения, объединения и разности выпуклых многоугольников через разбиение границ на фрагменты и сборку контуров.
  • bigint::exactTurn — точное вычисление (B − A) × (P − A) после приведения десятичных мантисс к общей степени десяти.
  • bezier::deCasteljau — линейная интерполяция уровней до одной точки; sample и composite строят полилинии для визуализации.

Сборка и запуск

cmake -S . -B build
cmake --build build -j2
./build/src/apps/GeometryWorkbench/GeometryWorkbench

Генерация API-документации

Нужен установленный doxygen:

doxygen Doxyfile

Главная страница будет создана в docs/site/html/index.html. Из CMake можно использовать цель:

cmake --build build --target docs

Doxyfile читает заголовки и исходники из src, извлекает публичные и приватные сущности и сохраняет HTML-дерево с исходниками и перекрёстными ссылками. Каталог docs/site/html — готовый статический сайт: его следует добавить в Git вместе с изменениями документации.

Публикация на GitHub Pages

В проекте есть workflow .github/workflows/deploy-docs.yml. Он не запускает Doxygen на сервере: workflow публикует уже подготовленный каталог docs/site/html на GitHub Pages. Поэтому после изменения комментариев, исходников или Doxyfile сначала локально выполните doxygen Doxyfile, затем добавьте обновлённый docs/site в коммит. Запуск происходит при изменении исходного кода, docs или Doxyfile в ветках main и master; его также можно запустить вручную через вкладку Actions.

Перед первым запуском в репозитории откройте Settings → Pages и выберите источник GitHub Actions. После успешного job Deploy to GitHub Pages ссылка на опубликованную документацию появится в его выводе и в разделе Pages. Для пользовательского домена настройте его там же: файл CNAME сам по себе домен не подключает.
