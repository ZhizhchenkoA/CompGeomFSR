# Проект 3. Автоматическое тестирование библиотеки `geometry`

Этот репозиторий содержит учебное Qt-приложение Geometry Workbench и независимую от Qt библиотеку геометрических алгоритмов. В проекте 3 для неё создана система автоматического тестирования по заданию «Система автоматического тестирования geometry»: отдельные исполняемые тесты, интеграция с CTest и проверка в GitHub Actions.

Тесты используют **Qt Test**, поскольку Qt уже требуется приложению. Сама библиотека `geometry` остаётся обычным C++: тестовый фреймворк подключён только к тестовым целям.

## Быстрый старт

Требуются CMake, компилятор с поддержкой C++17, Qt 5 или Qt 6 с компонентами Widgets и Test. На Debian/Ubuntu подходят `qtbase5-dev` либо `qt6-base-dev`.

```bash
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build -j2
ctest --test-dir build --output-on-failure
```

Если установлены обе версии Qt, для проверки конкретной версии добавьте при настройке `-DGEOMETRY_QT_VERSION=5` или `-DGEOMETRY_QT_VERSION=6`. CI задаёт этот параметр для каждой строки матрицы.

Запуск GUI-приложения: `./build/src/apps/GeometryWorkbench/GeometryWorkbench`. Для сборки приложения без тестов: `cmake -S . -B build -DBUILD_TESTING=OFF`.

## Что тестируется

| Набор CTest | Исходник | Основные сценарии |
|---|---|---|
| `geometry.predicates` | [`tests/test_predicates.cpp`](tests/test_predicates.cpp) | Левый/правый поворот, коллинеарность, совпадающие концы, допуск, принадлежность конечному и нулевому отрезку |
| `geometry.segments` | [`tests/test_segments.cpp`](tests/test_segments.cpp) | Пересечение, касание концом, параллельность, наложение, раздельные и вырожденные отрезки |
| `geometry.hull` | [`tests/test_hull.cpp`](tests/test_hull.cpp) | Пустой и минимальный вход, дубликаты, внутренние и коллинеарные точки, обход против часовой стрелки |
| `geometry.delaunay` | [`tests/test_delaunay.cpp`](tests/test_delaunay.cpp) | Пустой и вырожденный вход, окружность, четыре точки на одной окружности, покрытие площади |
| `geometry.polygon_boolean` | [`tests/test_polygon_boolean.cpp`](tests/test_polygon_boolean.cpp) | Перекрытие, раздельные и вложенные фигуры, общая сторона и вершина, совпадающие и пустые фигуры |

Подготовка общих сравнений координат собрана в [`tests/test_helpers.h`](tests/test_helpers.h). Каждый тест создаёт входные данные заново и не зависит от результатов или порядка других тестов.

## Интересные возможности системы

1. **Параметризованные сценарии Qt Test.** Пары методов `turnCases_data`/`turnCases` и `intersectionCases_data`/`intersectionCases` задают входные данные таблицей. В отчёте каждый вариант получает читаемое имя: например `proper-crossing`, `endpoint-touch`, `collinear-overlap`.
2. **Метаморфные проверки.** Не всегда нужно заранее знать все координаты ответа. Тесты проверяют свойства: разворот `AB` меняет знак поворота, перестановка двух отрезков сохраняет пересечение, перестановка и сдвиг входных точек сохраняют форму выпуклой оболочки.
3. **Проверка математического инварианта Делоне.** Для каждой полученной окружности тест проверяет, что ни одна другая входная точка не находится строго внутри неё. В отличие от сравнения со списком конкретных треугольников это допускает несколько корректных триангуляций для точек на одной окружности.
4. **Вырожденные случаи рядом с обычными.** Нулевая длина отрезка, совпадающие точки, коллинеарность, касание и пустой вход имеют отдельные сценарии. Они часто ломаются при небольших изменениях условий в алгоритме.
5. **Быстрый выбор нужной области.** `ctest -R geometry.hull --test-dir build --output-on-failure` запускает одну область; `ctest -L geometry --test-dir build` использует метки CTest; `ctest --test-dir build -N` показывает зарегистрированные цели без запуска.
6. **Повторение и подробный вывод.** `ctest --test-dir build --repeat until-fail:20 --output-on-failure` помогает заметить нестабильный тест; `build/tests/test_segments -v2` показывает отдельные сценарии Qt Test.
7. **Машиночитаемые отчёты.** `ctest --test-dir build --output-junit test-results.xml` создаёт JUnit XML; `build/tests/test_predicates -o result.xml,xml` создаёт подробный Qt Test XML. CI сохраняет отчёты как артефакты.
8. **Матрица Qt 5/6 в CI.** [Workflow](.github/workflows/test-geometry.yml) собирает проект и запускает тесты для обеих версий Qt при push и pull request. `fail-fast: false` показывает результат каждой версии независимо.
9. **Исчерпывающий перебор на маленькой сетке.** Тест `allSmallGridPairsAreSymmetric` проверяет все 6561 пары отрезков, составленных из девяти узлов сетки 3×3, включая нулевые отрезки. Для каждого случая сравниваются результаты при перестановке отрезков; порядок концов общей части не влияет на сравнение.
10. **Алгебра множеств через площади.** Для многоугольников проверяются равенства `S(A ∪ B) + S(A ∩ B) = S(A) + S(B)` и `S(A \ B) + S(A ∩ B) = S(A)`. Такой оракул проверяет целую операцию, не привязываясь к первой вершине контура.
11. **Регрессионный случай для общей границы.** Два прямоугольника, касающиеся всей стороной, обнаружили ошибку: объединение теряло контур. Исправление различает общие рёбра с одинаковым и противоположным направлением; тесты также охватывают частично общую и диагональную границы.
12. **Комбинаторные и геометрические свойства.** Перебираются все перестановки пяти точек оболочки; для Делоне проверяются число треугольников и суммарная площадь покрытия, в том числе при четырёх точках на одной окружности.
13. **Независимый геометрический оракул.** 36 прямоугольников на сетке 4×4 образуют 1296 упорядоченных пар. Для каждой пары тест независимо вычисляет площадь пересечения по координатам и проверяет площади пересечения, объединения и разности; это охватывает касания, вложения, совпадения и частичное перекрытие.

## Как устроена интеграция

Корневой [`CMakeLists.txt`](CMakeLists.txt) включает CTest и добавляет каталог [`tests/`](tests/CMakeLists.txt) при `BUILD_TESTING=ON`. Для каждого алгоритма создаётся отдельная цель `test_*`, подключаются `geometry` и `Qt::Test`, а `add_test()` регистрирует команду для CTest. `AUTOMOC` генерирует метаданные классов Qt Test. Дополнительных сторонних зависимостей и скачивания библиотек при настройке CMake нет.

## Что показать на защите

1. Выполнить три команды из «Быстрого старта» и показать `100% tests passed`.
2. Открыть `tests/test_segments.cpp`: объяснить разницу между `None`, `Point` и `Overlap`, показать касание концом и два нулевых отрезка.
3. Для демонстрации чувствительности тестов **временно** поменять в `src/lib/geometry/predicates.cpp` условие `if (value > tolerance)` на `if (value < tolerance)`, пересобрать и выполнить `ctest --test-dir build -R geometry.predicates --output-on-failure`. Тест `turnCases:left` должен упасть. Вернуть условие обратно и повторить тесты. Не включать намеренную ошибку в коммит.
4. Пояснить метаморфные проверки: они страхуют от ошибок даже без заранее записанного полного эталонного результата.
